# Архитектурная схема

## Общая схема взаимодействия компонентов

![Архитектура системы](architectural-scheme.jpg)

## Описание компонентов

- Клиент (React) - веб-интерфейс пользователя
- API Gateway - единая точка входа, маршрутизация запросов
- Пользователи + Пакты - основной сервис бизнес-логики
- Платежи - сервис обработки транзакций
- Email-сервис - отправка уведомлений на почту
- СУБД - хранение данных (PostgreSQL)
- Брокер - очередь сообщений (Kafka)
- API Tinkoff OFD - внешний платёжный шлюз

## Поток данных

1. User → Клиент (React): пользователь взаимодействует с интерфейсом
2. Клиент → API Gateway: все запросы идут через шлюз
3. API Gateway → Микросервисы: маршрутизация по доменам
4. Микросервисы → СУБД: сохранение и чтение данных
5. Платежи → API Tinkoff OFD: интеграция с платёжной системой (если нужно)
6. Сервисы → Брокер → Email-сервис: асинхронная отправка уведомлений
